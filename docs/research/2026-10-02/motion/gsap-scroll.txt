<div class="theme-admonition theme-admonition-tip admonition_xJq3 alert alert--success"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 12 16"><path fill-rule="evenodd" d="M6.5 0C3.48 0 1 2.19 1 5c0 .92.55 2.25 1 3 1.34 2.25 1.78 2.78 2 4v1h5v-1c.22-1.22.66-1.75 2-4 .45-.75 1-2.08 1-3 0-2.81-2.48-5-5.5-5zm3.64 7.48c-.25.44-.47.8-.67 1.11-.86 1.41-1.25 2.06-1.45 3.23-.02.05-.02.11-.02.17H5c0-.06 0-.13-.02-.17-.2-1.17-.59-1.83-1.45-3.23-.2-.31-.42-.67-.67-1.11C2.44 6.78 2 5.65 2 5c0-2.2 2.02-4 4.5-4 1.22 0 2.36.42 3.22 1.19C10.55 2.94 11 3.94 11 5c0 .66-.44 1.78-.86 2.48zM4 14h5c-.23 1.14-1.3 2-2.5 2s-2.27-.86-2.5-2z"></path></svg></span>Feature Highlights</div><div class="admonitionContent_BuS1"><ul>
<li class=""><strong>Link any animation to a particular element</strong> so that it only plays when that element is in the viewport. This improves performance and ensures that your beautiful animations actually get seen!</li>
<li class="">ScrollTriggers can perform an actions on an animation (play, pause, resume, restart, reverse, complete, reset) when entering/leaving the defined area or link it directly to the scrollbar so that it acts like a <strong>scrubber</strong> (<code>scrub: true</code>).</li>
<li class=""><strong>Soften the link between the animation and the the scrollbar</strong> so that takes a certain amount of time to &quot;catch up&quot;, like <code>scrub: 1</code> would take one second to catch up.</li>
<li class=""><strong>Integrated with <a class="" href="/docs/v3/Plugins/ScrollSmoother">ScrollSmoother</a></strong>, GreenSock&#x27;s smooth-scrolling tool built on native scroll technology (members-only benefit).</li>
</ul><details class="details alert alert--info details"><summary><strong>read more...</strong></summary><div class="details__inner"><ul>
<li class=""><strong>Snap to certain points in the animation</strong> based on velocity. In fact, you can <code>getVelocity()</code> of the scrolling anytime. Snap to the closest label in a timeline or progress value in an Array, or run your own custom function-based logic for snapping</li>
<li class=""><strong>Embed scroll triggers directly into any GSAP animation</strong> (including timelines) or create <strong>standalone instances</strong> and tap into the rich callback system to do anything you want.</li>
<li class=""><strong>Advanced pinning</strong> capabilities can lock an element in place between certain scroll positions. Padding is automatically added to push other elements down accordingly, so they catch up when the element gets unpinned (disable this with <code>pinSpacing: false</code>). You can even pin the same element multiple times at different points.</li>
<li class=""><strong>Incredible flexibility for defining scroll positions</strong> - like <em>&quot;start when the center of this element hits the center of the viewport, and end when the bottom of that other element hits the bottom of the viewport&quot;</em>, use keywords (top, center, bottom, left, right), percentages, pixels, or even relative values like <code>&quot;+=300px&quot;</code>. Once you get the hang of the syntax, it&#x27;s remarkably intuitive.</li>
<li class="">Accommodates <strong>vertical or horizontal scrolling</strong>.</li>
<li class=""><strong>Rich callback system</strong> including onEnter, onLeave, onEnterBack, onLeaveBack, onToggle, onUpdate, onScrubComplete, and onRefresh.</li>
<li class=""><strong>Automatically recalculates positions</strong> when the window resizes.</li>
<li class=""><strong>Enable visual markers</strong> during development to see exactly where the start/end/trigger points are. Customization options abound, like <code>markers: {startColor:&quot;green&quot;, endColor:&quot;red&quot;, fontSize:&quot;12px&quot;}</code>.</li>
<li class=""><strong>Toggle a CSS class</strong>. For example, <code>toggleClass: &quot;active&quot;</code> adds the &quot;active&quot; class to the trigger element while the ScrollTrigger is active. You can affect other elements too.</li>
<li class=""><strong>Responsive</strong> - use the <a class="" href="/docs/v3/GSAP/gsap.matchMedia()">matchMedia()</a> method to create different setups for various screen sizes using standard media queries.</li>
<li class=""><strong>Custom containers</strong> - you don&#x27;t need to use the viewport; define a custom scroller like a <code>&lt;div&gt;</code> instead.</li>
<li class=""><strong>Highly optimized for maximum performance</strong> - scroll events are debounced, updates are synchronized with GSAP and screen refreshes, resize recalculations are throttled, etc.</li>
<li class=""><strong>No scroll-jacking</strong>, so it can be combined with native technologies like CSS scroll snapping. If you want scroll-smoothing, you can use <a class="" href="/docs/v3/Plugins/ScrollSmoother">ScrollSmoother</a> which integrates seamlessly with ScrollTrigger, or use the <a class="" href="/docs/v3/Plugins/ScrollTrigger/static.scrollerProxy()">scrollerProxy()</a> method to integrate with a 3rd party smooth-scrolling library.</li>
</ul></div></details></div></div>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="faqs">FAQs<a href="#faqs" class="hash-link" aria-label="Direct link to FAQs" title="Direct link to FAQs" translate="no">​</a></h2>
<div class="faq"><details class="details alert alert--info details"><summary><h4>How does ScrollTrigger work? Is it just like IntersectionObserver?</h4></summary><div class="details__inner"><div class="answer"><p>ScrollTrigger does <strong>NOT</strong> constantly watch every element and check its positioning in the viewport on each tick. We&#x27;re obsessed with performance and that&#x27;d be far too costly. Instead, ScrollTrigger does the processing up-front to figure out where the start/end points are <em>in the natural document flow</em>. In other words, <em>&quot;this ScrollTrigger will be active when the scrollbar is between ___ and ____&quot;</em>. Then, it debounces the &quot;scroll&quot; events and only updates things on the next requestAnimationFrame, perfectly synced with GSAP and screen refreshes. It <strong>ONLY</strong> watches the scroll position. <strong>Period.</strong> That means it&#x27;s <strong><em>FAST</em></strong>.</p><p>ScrollTrigger automatically listens for viewport/scroller &quot;resize&quot; events and recalculates all the start/end positions accordingly (<code>onRefresh</code>). In fact, since resizing/refreshing is CPU-intensive, it waits until there&#x27;s a 200ms gap in resize events before starting its work. Yeah, we looked for every opportunity to maximize performance.</p><p><a href="https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API" target="_blank" rel="noopener noreferrer" class="">IntersectionObserver</a> is a native feature in most modern browsers that&#x27;s different in the following ways:</p><ul>
<li class="">It constantly &quot;watches&quot; elements to sense when they enter/leave regardless of scrolling.</li>
<li class="">It&#x27;s <strong>not</strong> helpful for tracking an element&#x27;s position between two points, like for scrubbing an animation accordingly.</li>
<li class="">It does let you watch multiple elements and have a single callback triggered that could loop through and fire a staggered animation on just the elements that entered, for example.</li>
</ul><p>ScrollTrigger does not use IntersectionObserver under the hood because it lacks the necessary functionality and compatibility. You can certainly use IntersectionObserver and ScrollTrigger together.</p></div></div></details><details class="details alert alert--info details"><summary><h4>How does pinning work under the hood?</h4></summary><div class="details__inner"><div class="answer"><ul>
<li class="">The pinned element gets immediately wrapped in a <code>&lt;div&gt;</code> with a <strong>fixed</strong> width/height to match. A class of &quot;pin-spacer&quot; is added to that wrapper. Think of it like a proxy element that props open the space where the pinned element was in the DOM so that when it flips to <code>position: fixed</code> things don&#x27;t collapse.</li>
<li class="">By default, padding will be added to the bottom (or right for horizontal: true) of the pin-spacer so that [in most cases] things get pushed further down/right. When the pinned element gets unpinned, the content below/right will have caught up. So if, for example, the pinned element stays pinned for 300px, there would be padding of 300px added.</li>
</ul><div class="theme-admonition theme-admonition-info admonition_xJq3 alert alert--info"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 14 16"><path fill-rule="evenodd" d="M7 2.3c3.14 0 5.7 2.56 5.7 5.7s-2.56 5.7-5.7 5.7A5.71 5.71 0 0 1 1.3 8c0-3.14 2.56-5.7 5.7-5.7zM7 1C3.14 1 0 4.14 0 8s3.14 7 7 7 7-3.14 7-7-3.14-7-7-7zm1 3H6v5h2V4zm0 6H6v2h2v-2z"></path></svg></span>walkthrough</div><div class="admonitionContent_BuS1"><iframe allow="autoplay; fullscreen" allowfullscreen="" frameborder="0" src="https://player.vimeo.com/video/439964874?byline=0&amp;title=0&amp;portrait=0" class="fr-draggable video"></iframe><p>This video on pinning that&#x27;s part of SnorklTV&#x27;s <a href="https://www.creativecodingclub.com/courses/scrolltrigger-express?ref=44f484" target="_blank" rel="noopener noreferrer" class="">ScrollTrigger Express course</a> may help your understanding.</p></div></div><ul>
<li class="">When the ScrollTrigger is active (when the scroll position is between the start and end), it sets the pinned element to <code>position: fixed</code> and positions it with fixed top/left/width/height values...unless the scroller isn&#x27;t the viewport in which case it never uses <code>position: fixed</code> because that&#x27;d break sub-scrolling, so it uses pure transforms. If <code>pinReparent</code> is set to <code>true</code> (we recommend avoiding that if you can), the pinned element will get reparented to the <code>&lt;body&gt;</code> and styles will be moved inline to ensure appearance is maintained.</li>
<li class="">When the ScrollTrigger becomes inactive, the pinned element reverts to its original <code>position</code> value and a <strong>transform</strong> is applied to place it correctly.</li>
<li class="">When the window/scroller gets resized, all ScrollTriggers re-calculate their start/end positions (<code>onRefresh</code>). As a part of that process, the pin-spacer is removed from the DOM and the pinned element is swapped back in so that measurements are accurate with the original CSS. Then the pin-spacer is swapped back in as a wrapper.</li>
</ul><p>Why not just use transforms and avoid <code>position: fixed</code>? Many browsers don&#x27;t render consistently using that technique. There are annoying visual glitches due to the fact that scroll repaints are handled on a different thread in most modern browsers. Surprisingly, <code>position: fixed</code> seemed to deliver better performance overall. And performance is EXTREMELY important for scrolling.</p></div></div></details><details class="details alert alert--info details"><summary><h4>How does duration work with scrub: true?</h4></summary><div class="details__inner"><div class="answer"><p>If you have a ScrollTrigger <code>scrub: true</code> and that ScrollTrigger has a timeline or tween animation associated with it, the durations of tweens within that animation serve as proportions for the total amount of distance that the tween will play. The proportion of how much distance it&#x27;s animated between is in regards to the total duration of the animation. It&#x27;s easiest to understand with an example:</p><p>Say you have a timeline with three sequenced tweens: a 1 second tween, a 3 second tween, and then another 1 second tween. And the ScrollTrigger applied to it will animate for a full viewport height&#x27;s distance (perhaps the trigger uses the values of <code>start: &quot;center bottom&quot;</code> and <code>end: &quot;center top&quot;</code>).</p><p>If <code>scrub: true</code> (or a number) is applied, then the first tween will be animated between when the center of the trigger element is between the 100% mark (from the top; the bottom of the viewport) and the 80% mark (from the top) of the viewport. The second tween will fire when the center of the element is at the 80% mark until the 20% mark. And the third tween will fire when the center of the element is between the 20% mark and the 0% mark. This is because the total duration of the timeline is 5 seconds. So ⅕ is 20% and ⅗ is 60%.</p><div class="codepen--loading"><h4>loading...</h4><iframe height="400" style="width:100%" title="GSAP Basic Tween" src="https://codepen.io/GreenSock/embed/yLegBwO?default-tab=result&amp;theme-id=41164" frameborder="no" allowtransparency="true" allowfullscreen=""></iframe></div><p>If you change the duration of all the tweens to the same number, say 1, then the percentages would all be equal: 100% -&gt; 66%, 66% -&gt; 33%, 33% -&gt; 0%. This is because the total duration is 3, so ⅓ is 33%.</p><p>In other words, the duration values don&#x27;t matter as much as the proportions of the duration of each tween compared to the total time of the timeline.</p><p>If you want to make the animation take a longer distance of scroll to complete, affect the distance from start to end longer. For example you could set <code>end: &quot;+=4000&quot;</code> to make it take a lot of scrolling to complete.</p></div></div></details></div>

You can learn more about it <a href="https://gsap.com/resources/st-mistakes#nesting-scrolltriggers-inside-multiple-timeline-tweens" target="_blank">here</a></p></span></div></div></div></div></div></details><details class="accordion-row" data-block="accordion-row"><summary class="accordion-row__heading"><h4>How can I hook up a Lottie animation to ScrollTrigger?</h4><div class="accordion-row__button"><svg width="19" height="18" viewBox="0 0 19 18" fill="none" xmlns="http://www.w3.org/2000/svg"><line class="accordion-plus__line-1" x1="0.214844" y1="8.77966" x2="18.2148" y2="8.77966" stroke="var(--ifm-heading-color)" stroke-width="1.5"></line><line class="accordion-plus__line-2" x1="8.99425" y1="18.0001" x2="8.99425" y2="0.000122103" stroke="var(--ifm-heading-color)" stroke-width="1.5"></line></svg></div></summary><div class="accordion-row__answer"><div class="accordion-row__answer-inner"><div class="grid"><div class="col col-tablet-8 col-tablet-start-5"><div><span><p>It's quite easy, actually - we've even got a <a href="/docs/v3/HelperFunctions#lottie">helper function</a> for that.&nbsp;</p></span></div></div></div></div></div></details><details class="accordion-row" data-block="accordion-row"><summary class="accordion-row__heading"><h4>What version of GSAP is required?</h4><div class="accordion-row__button"><svg width="19" height="18" viewBox="0 0 19 18" fill="none" xmlns="http://www.w3.org/2000/svg"><line class="accordion-plus__line-1" x1="0.214844" y1="8.77966" x2="18.2148" y2="8.77966" stroke="var(--ifm-heading-color)" stroke-width="1.5"></line><line class="accordion-plus__line-2" x1="8.99425" y1="18.0001" x2="8.99425" y2="0.000122103" stroke="var(--ifm-heading-color)" stroke-width="1.5"></line></svg></div></summary><div class="accordion-row__answer"><div class="accordion-row__answer-inner"><div class="grid"><div class="col col-tablet-8 col-tablet-start-5"><div><span><p>3.3.0 or later.</p></span></div></div></div></div></div></details></div>
