# Whole-page visual diagnosis — production c06792d

Date: 2026-10-03. Scope: independent, read-only review of the approved C artwork and the actual static production export served at `http://127.0.0.1:3040`. The user's latest rejection supersedes earlier bounded typography approval. No source or asset bytes were edited in this audit.

## Evidence and scope

Reference: `docs/research/2026-10-03-concept-reset/mockups/c-name.png` (1536×1024), `c-mobile.png` (853×1844), and `c-storyboard.png` (six chapters). Current screenshots: `old-production/`; measured runtime rectangles: `old-production/geometry.json`.

Captured Chromium at 1536×1024, 1024×768, 884×680, 801×900, 800×1024, 390×900, and 1920×1080. Captured the three project chapters, engineering, playground, and about at desktop, narrow desktop, and phone. Motion was paused after scene readiness so comparisons use production assets without the dev image optimiser. Desktop chapter images at +0.20 viewport intentionally show a transition state; those images must not be presented as the completed mechanism. Actual browser zoom was not measured: 884×680 is a small CSS viewport representing similar layout pressure, not a claim to reproduce the user's exact browser configuration.

The important finding is that lack of horizontal document overflow does **not** mean a usable responsive composition. Every captured size reports no horizontal overflow, while 801px and 800px both visibly collide.

- At every width, cap text size and frame text should stay readable in CSS pixels. A responsive layout must gain vertical room or change its composition when necessary; it should not simply shrink an entire reference raster.

## Verification that would address the actual failure

A future verification report should separately cover hero copy/face collisions, caption/card/proof intersections across all orbit phases, layout on either side of composition changes, header contrast, reading order, keyboard targets, real wheel reverse, and mobile Remotion legibility. The old rectangle checker tests chapter copy against focused frames but never tests hero face/name/body/card collisions; its zero-collision result cannot certify this surface.

This audit did not claim Safari, Firefox, iOS hardware performance, actual browser zoom, or whole-site acceptance. It inspected current Chromium production and the supplied visual authority. The user remains the final judge of the visual result.
